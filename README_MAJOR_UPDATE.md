# Career Hub — comprehensive upgrade

This combines the latest cloud-account, email registration and closed-vacancy packages. All existing 78 practice modules and hourly search workflow are retained. The new applicant tools work locally without a new paid API.

## Upgrade safely
1. Export your current workspace from Account. Save to cloud if desired. **Each signed-in account now has its own local workspace. Old local data stays in the guest workspace; restore the cloud backup or import your exported file into your signed-in workspace.** Do not import another person's data.
2. Fetch/pull your existing GitHub Desktop repository. Copy the files in this ZIP over the corresponding files. Do not replace `site/config.js`, `site/cloud-config.js`, `site/feedback-config.js`, `site/vacancies.json`, or an existing custom `employer_sources.json`. These files are deliberately omitted from this upgrade.
3. If installing the original major upgrade for the first time and enabling its private features, review the included `config-examples/firestore.rules.example` for Firebase (back up existing custom rules first). This changes access permissions, not stored accounts or backups. Before public use, test unauthenticated access and separate user IDs with the Rules Playground. Rules include the existing owner-only backup collection plus private reports, administrator membership, announcements and optional email subscriptions.
4. Commit and push. GitHub Actions runs the release checks, then the existing hourly search and link checks, generates the new public pages and deploys. Refresh the website. The service worker has a new version; if it shows old assets, clear the service worker cache without clearing your local workspace.

## New features
- Public welcome panel for new visitors; direct dashboard access for returning users.
- Applicant essentials: CV health check, editable cover-letter draft, pasted recruitment email importer (no email account access; explicit approval before status change), industry interview questions, technical practice shortcuts, work experience resources and reminders, commute/relocation calculator, vacancy alerts and missing vacancy form.
- Reasoning modules: difficulty choice, untimed mode, per-question answer review, average response time and response-time variation. Independent assessment exercises, not official tests.
- Private reports and missing vacancy submissions for verified Firebase users. Public GitHub feedback remains available.
- Account-specific local workspace storage. This is isolation in the app, not encryption; someone with access to browser developer tools can read local data. Use separate browser profiles on shared computers. Export before changing account, clearing storage or removing a profile. Cloud backups are explicit and retain the existing format.
- In-app matching and deadline/reopening alerts, supported employer-board discovery from known public vacancy URLs, stronger deduplication and history fields. Board discovery is capped at 30 additional feeds to protect runtime and avoid excess calls. No paid search API; not a complete crawl of the internet. The existing employer feeds are retained, including AJ Bell. Respect provider terms and review discovered board use permissions.
- Individual crawlable vacancy and employer pages, four guidance articles, favicon, canonical links, sitemap, shareable vacancy URLs. Generated public pages are not application data. Only published facts are shown. Closed adverts retain reference pages but are omitted from the vacancy sitemap. JobPosting markup is intentionally not activated for imported listings without sufficient permission and complete verified fields; do not claim Google Jobs eligibility just from a sitemap.
- Support remains accessible across the app and generated public pages. Search Coverage remains removed.

## Enable private administration
1. Sign into your Career Hub account and verify the email. In Firebase Authentication → Users, copy your UID.
2. In Firestore Data, create a collection `career_admins`. Add a document with ID exactly your UID and a field `role` (string) with value `admin`. Only use the Firebase console to assign admins. Ordinary users cannot write this collection.
3. Open the website and sign in again. Administration appears after membership is checked. You may also open `https://playerlad2-hub.github.io/Apprenticeship/#admin`.
4. Review, resolve or delete private reports and publish an announcement. User counts, employer registry edits, deployment logs and question management are still managed in Firebase or GitHub (links provided); the browser never gets Firebase admin credentials or access to private backups of other users.

## Optional daily email alerts
In-app alerts already work. Email delivery is **off by default**: GitHub Pages cannot send email itself. `send_alerts.py` is an optional private runner. Do not store any server credentials or subscriber data in a public repository or public Actions cache. Use an eligible, authorised SMTP relay with suitable sending limits and a trusted computer/private runner; free allowances vary. Install `firebase-admin` in a separate Python environment. Configure Application Default Credentials for an appropriately authorised Firebase service identity privately; use least privilege and revoke credentials if no longer needed. Configure `CAREER_SMTP_HOST`, `CAREER_SMTP_PORT` (SSL, default 465), `CAREER_SMTP_USER`, `CAREER_SMTP_PASSWORD`, `CAREER_MAIL_FROM` privately as environment variables. The runner checks verified email, opt-in and fresh vacancy data; a daily delivery ledger prevents repeated sends. Run `python send_alerts.py` first for a dry run. After a successful controlled test, use `python send_alerts.py --send` in your private daily scheduler, and set `window.CAREER_EMAIL_ALERTS_ENABLED = true` in `site/alerts-config.js`. Users can unsubscribe in Applicant essentials → Vacancy alerts. Do not enable email until the sender, unsubscribe and deletion flows have been verified. No mail was sent in testing.

## Google Search Console
Add the actual website URL as a URL-prefix property, verify ownership using a supported method, then submit `https://playerlad2-hub.github.io/Apprenticeship/sitemap.xml`. Hourly deployment regenerates it. Search indexing/ranking is not guaranteed. For Google Jobs, review https://developers.google.com/search/docs/appearance/structured-data/job-posting and obtain the rights/complete current data needed to publish compliant JobPosting markup.

## Privacy and launch checklist
The in-app privacy notice is a starting point, not a legal compliance certificate. Fill in controller identity/contact, lawful bases, retention, data rights and processor details before inviting public registration. Minimise personal data, especially because many visitors may be minors; see ICO Children's Code. Review provider terms and get appropriate guardian involvement where required. Set clear moderation/retention policies and test all account flows live. Account deletion deletes the cloud backup and login; exported files and other devices' local copies remain. The admin can remove old feedback. No private user data is published in the generated pages or vacancy cache.

## Tests
Run `python tests/check_release.py` with Python and Node installed. It checks JavaScript syntax, URL allowlisting, safe static HTML generation and closed-vacancy sitemap behaviour. The new local UI was exercised in isolated Chromium (not a live hosted deployment). Firebase and SMTP services need live configuration and validation. Direct navigation was blocked in the test environment. No exhaustive verification of every assessment item, every vacancy, Firebase rules emulator or Google indexing was performed.
